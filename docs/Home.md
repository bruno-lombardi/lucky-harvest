# Lucky Harvest Wiki

Lucky Harvest is an isometric 3D farming game (TypeScript, Vite, Three.js) in the spirit of *Happy Harvest* from the Orkut days. Every model, texture and sound is generated by code: there are no art or audio assets. The interface is in Brazilian Portuguese; the code and these docs are in English.

This wiki explains how the codebase is organised, why it is organised that way, and where to go next. Start with **Architecture**, then read whichever page matches what you are about to change.

## The three ideas that shape everything

1. **The rules are a pure function.** `src/core` never reads a clock, never calls `Math.random`, and never imports Three.js or the DOM. Given a state, a command and a timestamp it always produces the same new state. This is what will let a server replay a player's actions and agree with the client.
2. **Everything the player does is a `Command`.** A command is plain serialisable data (`{ type: 'buySeeds', crop: 'milho', qty: 3 }`). The UI never mutates the farm directly; it dispatches a command, the engine applies it, and the screens redraw from the new state.
3. **Rendering and UI are read-only views.** `FarmView`, `Pens`, `HelperView` and the dialogs look at the `Farm` and draw it. They keep their own animation state but never change game state, so they can be rewritten, or replaced by a spectator view of someone else's farm, without touching the rules.

## Reading the code

Every module starts with an `@module` comment that says what it is, how it connects, and what to respect when editing it. Places where future work will plug in are tagged so you can find them with a search:

- `NEXT(backend)`: server authority, sync, accounts, clocks.
- `NEXT(multiplayer)`: visiting, gifts, helping, stealing, markets, shared state.
- `NEXT(content)`: seasons, events, quests, cosmetics, localisation.

```bash
grep -rn "NEXT(backend)" src
```

## Quick facts

- Entry points: `index.html` → `src/main.ts` (wires everything) → `src/game.ts` (renderer and loop).
- Roughly 18,000 lines of TypeScript, about 180 tests (`npm test`).
- Pushes to `main` run tests, build, and deploy to GitHub Pages.
- Save data lives in the browser (`localStorage`), in a versioned, checksummed file that also carries a command log for a future server.
